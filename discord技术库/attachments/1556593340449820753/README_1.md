# MMD 美化积木工坊

给新人作者用的 MMD 界面美化生成器：**左边勾积木 → 中间实时预览 → 右边一键导出「导入正则」JSON**。
单文件、零外链、离线可用，双击 `index.html` 就行。

```
MMD美化积木工坊/
├── index.html        工具本体（单文件，无任何外部依赖）
├── self-test.mjs     自测：抽纯逻辑 → 造 6 份产物 → 跑 skill 的 validate.mjs + 6 组专项断言
├── inspect-any.mjs   命令行版皮肤医生：批量体检任意「导入正则」JSON
└── fixtures/         自测生成的 6 份代表性「导入正则」JSON，可直接导进创卡页试
```

---

## 三步上手

1. 打开 `index.html`，左边勾积木：配色 → 气泡 → 顶栏 → 底栏 → 粒子 → 动效 → 一键开关按钮 → 宿主弹窗。
   中间随时看效果，可以用「☀️ 日间 / 🌙 夜间」切 MMD 的两套主题，用「🖥️ 桌面 / 📱 手机」切视口。
2. 点「📋 复制 JSON」（或「⬇️ 下载 .json」）。
3. 回到 MMD **创卡页 → 导入正则** → 粘贴这个 JSON → 然后**回到聊天页**看真实效果。

> 创卡页的预览是瘦环境：`input` / `save` / `message.send` 一律 `NOT_SUPPORTED`，脚本和输入框都不生效。
> 新建卡时必须在创卡页确认这张卡走的是**新版聊天页**——JSON 里的 `chatVersion: 1` 只在新建卡时被读取。
> 手机调试给聊天页地址加 `?sdkDebug=1`。

## 工具会生成哪些规则

| scriptName | 匹配式 | 内容 |
| --- | --- | --- |
| `skin-vars` | `{{skin-vars}}` | 语义变量 + 几何令牌 + 18 个宿主主题变量（日夜各一套） |
| `skin-layout` | `{{skin-layout}}` | 顶栏 / 头像 / 气泡 / 底栏 / 功能栏 / 开关按钮 |
| `skin-fx` | `{{skin-fx}}` | 粒子（伪元素 + 径向渐变）与动效、`prefers-reduced-motion` 兜底 |
| `skin-host` | `{{skin-host}}` | 宿主弹窗细化，每条从精确 `[data-host="…"]` 根开始 |
| `skin-custom` | `{{skin-custom}}` | 你在「高级」里追加的 CSS |
| `skin-btn` | `{{skin-toggle}}` | 只有把开关按钮塞进功能栏时才生成；`statusbar` 字段被写成 `{{skin-toggle}}` |
| `skin-kit` | `{{skin-kit}}` | 一键开关脚本（读上次选择 / 切 `.mmdskin-off` / 改按钮文字） |

匹配式一律用 `{{skin-xxx}}` 占位串：平台不建议在匹配式里出现 HTML 标签与 `html` / `head` / `body` / `css` 这些保留字。
`<style>` / `<script>` 规则不需要被谁引用——装卡时会被平台抽走；只有产出**可见 HTML** 的 `skin-btn` 才需要触发串出现在 `statusbar` 里。

## 📤 导出形态与导入兼容（v1.7）

拿平台自己导出的《角色卡【315513】正则数据.json》当基准逐项对齐：

| | 平台自己导出的 | 工具现在的默认 |
| --- | --- | --- |
| 顶层键 | `pageDepth, statusbar, beginning, regex_scripts` | 上面四个 **+ `chatVersion: 1`** |
| 排版 | 单行紧凑（**实测回灌不生效**） | **缩进多行（实测有效）** |
| 脚本结束标签 | **原样不转义** | **原样不转义** |
| 规则的 `id` | **每条都是 `-1`** | **每条都是 `-1`** |
| 规则的键顺序 | `id, replaceString, scriptName, findRegex` | 同上 |

### ⚠️ 排版这一行是实测出来的反直觉结论

用户拿真实导入页反复试出来的：

- **单行紧凑的 JSON：导入页不报错，但规则不生效**（试了两次，两次都这样）
- **缩进多行的 JSON：正常生效**

同样内容、只差外层排版，效果却不同 —— 平台内部怎么处理的不清楚。工具因此**只出缩进多行**，那个「JSON 排版」选项已经删掉；自测里有一条断言专门守着它，防止有人（包括我）为了"跟平台文件同形"又改回单行。

> 顺带一个推论：平台自己导出的紧凑文件，**未必能可靠地回灌**。真要给已有卡做备份/迁移，建议导出后先手动存一份缩进版的。

- **`statusbar` / `beginning` 是必带的键，哪怕值是空串。** 少了它们，导入页会判「格式错误」—— 这是真实踩过的坑：平台自己导出的 4 份文件里这两个键一个都没少。
- **`chatVersion: 1`** 是给新建卡用的（决定这张卡走新版聊天页）。平台从已有卡导出的文件里没有它，因为那是导入时才读的字段，文档把它列在导入白名单里。
- **不转义脚本结束标签**也是为了跟平台同形：它的文件里就是原样的写法，而这份 JSON 只用于导入、不会被嵌进 HTML。
- **规则的 `id` 一律写 `-1`**，不再用 `-1 / -2 / -3 …`。依据是平台自己导出的 4 份文件里**每条规则的 id 都是 `-1`**：`-1` 很可能是「新建一条」的哨兵值，而别的负数可能被导入当成「更新已存在的第 N 条」。宁可跟平台产出一致，也不自作聪明。
  > 代价要说清楚：本 skill 的 `validate.mjs` 会把「id 重复」报成 **error**。这条规则比平台实际行为严格 —— 平台自己的导出文件正因为这样，拿它跑同一个脚本也会报重复。
  > **工具自己的检查器干脆不报这条**（重复是刻意的设计，不是问题），只检查「id 必须是负整数」；所以工具里的「自检报告」不会再为它标黄。皮肤医生分析别人的包时同理。
- 「JSON 排版」可切成缩进美化方便自己读；默认保持紧凑最保险。
- ⚠️ **给已有卡导入前**：把「导出形态」里的 `statusbar` / `beginning` 填成你卡里原本的内容——**空字符串等于清空它们**。最稳的办法是用平台自带的导出功能导一次自己的卡，把这两个值原样贴进来。

## 一键开关是怎么做到的

所有皮肤规则都挂在 `[data-chat="root"]:not(.mmdskin-off)` 下。按钮点一下 → 切换根节点上的 `.mmdskin-off` 类 → 整套颜色、布局、粒子同时失效，回到平台原生样子。

- 没用 `:has()`，没覆盖平台内部 class，没碰 `window.parent.document`。
- 按钮自身样式**不带**这个前缀，否则关掉美化后按钮会跟着消失、就再也开不回来了。
- 状态可以存 `sdk.cache`（刷新即失）或 `sdk.save`（永久，占一个作者存档名；写入限频 20 次/分钟，只在点按钮时写一次）。
- 脚本自己有 `window.__mmdSkin` 幂等守卫，被重复注入也不会多绑一次点击。

---

## 粒子为什么不用脚本

粒子是 `::before` / `::after` 两个伪元素，用多层 `radial-gradient` 平铺出上百个点，动画走 `transform` 交合成层。

- 不新增 DOM 节点、不写脚本（脚本被平台抽走也照样在）、不逐帧重绘整页。
- 两层不同 tile 尺寸与速度 → 远近纵深；`transform` 位移量正好等于一个 tile 周期 → 无缝循环。
- 形态（星尘 / 萤火 / 雪花 / 花瓣 / 气泡）、密度、大小、速度、透明度、方向都能调。

## 🩺 皮肤医生（手里已经有现成包的时候）

右上「皮肤医生」页可以粘一份现成的「导入正则」JSON，或者直接选文件（工作目录里那份《角色卡【315513】正则数据.json》就能直接拖进去）。
它是**纯只读**分析，不会改动那份包的任何一个字节，输出：

- **旧版特征清单**：`chatVersion` 不是 1、裸父页面选择器（`.sandbox-host` / `.model-setting-scope`…）、拿 `:root/body/*` 当 CSS 根、完全没用 `--chat-*`、`url()` 外链、`【】` 旧切片协议、`[status]` / `〖骰=` / `teapot` / `$#char#$` 等旧标记、全篇看不到 `[data-chat]`
- **硬伤**：超长替换内容、重复的匹配式、编造的能力名、会产出可见内容却没有触发串、自写 `data-*`、四空格缩进的 HTML
- **会覆盖你卡里什么**：这份包带着 `statusbar` / `beginning` / `personality` 的话，导入时会盖掉对应字段（人设还得单独粘）
- **规则清单表**：每条的名字、匹配式类型与内容、替换内容字数、里面装的是样式/脚本/可见 HTML
- **配色提取**：把 `--chat-*` 归一成 9 键色板，能分日夜两套。点「🩹 用这套配色重建一份合规皮肤」就把色板套进左边的积木面板

**推荐的迁移姿势**：医生扒配色 → 套进积木面板 → 按现在的积木重新生成一份合规包。**不要**把旧版 `:root, body` 那套原样搬进新版。

配色归属的判断顺序（这是医生最讲究的地方）：先看选择器有没有 `data-theme="dark"/"light"`（最准）→ 再看**同一个 CSS 块里的变量属于同一套**（`--chat-bg` 是深是浅决定整块归到哪边）→ 最后才按每个键各自的策略兜底（`text/muted/bubbleText` 取亮的那支、`bg/border/bubble*` 取暗的那支、`accent` 按与背景的对比度挑）。
之所以不按明度一刀切：**暗色主题的强调色经常比亮色主题的还亮**，按明度排会一直挑反。

## 🔧 对比度一键修正

「自检报告」页每条对比度都标了 WCAG 比值。点「🔧 一键修正对比度」会**保持色相、只推明度**：

| 目标 | 阈值 |
| --- | --- |
| 正文 / 背景 | ≥ 7:1 |
| 次要文字 / 背景 | ≥ 4.5:1 |
| 气泡字 / AI 气泡 | ≥ 5:1 |
| 气泡字 / 我的气泡 | ≥ 4.5:1 |
| 强调色 / 背景 | ≥ 3:1（非文本） |

修完会逐条列出「旧色 → 新色（前比值 → 后比值）」；如果推完次要文字和正文一样亮，会再把次要文字往背景方向压一点，保住层级。手动改过任何一个颜色，之前那份清单自动作废。

## 🖼️ 拖一张参考图取色

不会配色的时候最有用：把插画／截图拖进「配色方案」最上面那块斜框里。

1. 图片在本地缩到最长边 180px，按 4bit/通道分桶统计频率，距离去重后取 8 个主色（丢掉纯黑纯白与半透明像素）；
2. 最「艳」的那个当强调色，最暗／最亮的当背景，其余用明度阶梯 + 主色的色相饱和度推成**日夜两套**完整色板；
3. 自动套用，并把你拖的图里抽出来的 8 个主色显示成色块。

图片只在浏览器内存里算像素，不上传、不保存。

### 取消与混搭（v1.6）

配方是**部分覆盖**：它只动自己 patch 里那几个键（外加推荐配色的 18 个颜色）。所以：

- **套用时先抓一份「改动前快照」** → 点「✕ 取消当前配方」就能把这批键还原成**点它之前的值**。快照存在 `localStorage` 的独立键里（不进 state、不进分享链接），所以刷新后依然能取消。
- **改任何一项都不会把配方弄丢**：它会留在原地并标注「**已混搭**」（胶囊变虚线），状态那一行会写明「当前配方：🌸 樱花雨（已混搭，不会自动跟着配方走）」。之前一改高亮就灭，会让人以为配方已经没了、其实还在生效 —— 那正是「取消不掉」的来源。
- **换另一套配方时，先把上一套整个还原**，再套新的。因为 patch 是部分覆盖：樱花雨设了 `header.radius` 而深海鲸歌没设，不还原就会把上一套的值留在身上（串味）。
- **没有快照时**（例如从别人的分享链接打开、或清了浏览器数据）取消会**回落到出厂默认值**，不会留着半套风格。
- 你在套用之后自己改过的项，取消时**也一并还原** —— 因为它们同属「这套配方动过的那批键」。这条规则写在工具里的配方提示里，不藏在代码里。

## 🔗 分享链接（v1.5）

「高级」里点「🔗 复制分享链接」：把**和默认不同的那部分** diff 出来，压进网址的 `#s1=` 后面。实测长度：

| 你的配置 | 链接长度 |
| --- | --- |
| 出厂默认 | 约 45 字符 |
| 只换了个配色预设 | 约 76 字符 |
| 一整套风格配方 | 约 466 字符 |
| 配方 + 手改颜色 + 自定义 CSS + 开场白 | 约 1.9K 字符 |

两个细节：

- **用现成预设时，18 个颜色值不会编进链接** —— 收链接的人按预设 id 自己推得出来。所以一套完整配方的链接只有 424 字符（不做这个优化是 1794）。顺带的好处：以后我调整预设色值，旧链接也不会给人过期的颜色。
- **打开带 `#s1=` 的地址会套用该方案，然后自动把 hash 清掉** —— 否则他每次刷新都会被你的方案覆盖掉自己的改动。

**限制（重要）**：本地用 `file://` 打开时，链接只有在**同样路径**的电脑上才打得开。要让别人一键复现，得先把 `index.html` 挂到网上（单文件，丢任何静态托管都行）。配置很大的话，用「导出方案 JSON」把文件发过去更稳妥。

## 顺手能省事的两处

- **导出压缩**：只删 CSS 注释、换行与行首缩进，**绝不动一行之内的空格**（`calc(100% + 760px)` 里的空格是语法要求）。嫌输出不好读就关掉。
- **自动拆条**：单条替换内容超过编辑器 20000 字上限时，按花括号深度安全拆成 `skin-xxx-2` / `-3`…，只在深度 0（规则之间）下刀，绝不切进 `@media` 或某条规则内部。
- **存档 key 可改**：选「永久记住」时能改 key 前缀（只留字母数字与 `_.-`），避开你自己卡里的存档名冲突（平台只有 10 个存档名）。

## 🛡️ 「保护自定义界面」与「残留防护」（v2.2）

### 问题一：皮肤会把卡自己的界面一起改掉

卡自己的 UI **就住在聊天消息里**——它和 AI 的文字气泡是同一批节点（`[data-chat="message"]` / `message-body`）。所以皮肤去改气泡时，卡那套面板也会被一起改。

但不是所有属性都一样危险。实测 + 用户反馈之后定位到的**真凶只有两个**：

| 属性 | 后果 | 处理 |
| --- | --- | --- |
| 气泡 `max-width` | 把卡的全宽面板**挤成窄条**（就是"美化渲染了整个界面"那种画面） | 受保护：默认写 `revert`，对应滑杆隐藏 |
| 消息 `transform`（气泡入场动画） | 卡里**固定定位**的面板在动画期间错位 | 受保护：默认写 `revert`，对应开关隐藏 |
| 气泡内边距 / 消息间距 / 头像尺寸 | 很温和，不会压坏面板 | **照常生效** |

> 这里有一段真实的返工：最初我把「不动布局」做得太宽，连**气泡内边距**一起 revert 了，结果气泡里的字紧贴边缘、看起来"挤成一团"。收紧到只护那两个真凶之后才正常。自测里因此多了一条断言：**默认状态下气泡内边距必须真的写出来**。

### 问题二：再次导入会有残留

平台的样式是**把所有规则的 `<style>` 合成一张表**。新皮肤对某个属性**不写**，旧皮肤写过的那个值就还留着 —— 于是出现"新配色 + 旧圆角"这种混搭。

对策：**每一个「关掉」的开关都显式写 `revert`**（CSS 的 revert 关键字＝把平台原样还回来）。自测里有 **19 种**"关掉某开关"的状态在守这条。

> 如果还看到残留，说明平台是**追加**规则而不是替换。两个办法：在卡的正则列表里把旧的皮肤规则删掉再导入；或者用一键开关把整套关掉（新旧规则都带 `.mmdskin-off` 前缀，会一起失效）。

### 另外

- **根节点不再强行写 `background-color`**：整页底色交给平台的 `--chat-bg` 变量，免得盖掉卡自己画的整页背景。

## 平台边界：能改什么、不能改什么

**能改**：`[data-chat]` / `[data-slot]` 选择器范围内的一切视觉；平台公开的 `--chat-*` 语义变量；写在 `[data-chat="root"]` 上的 18 个宿主变量；从精确 `[data-host="…"]` 根开始的受控宿主 CSS。

**不能改**：
- 父页面弹窗的 DOM、业务逻辑、跨源脚本 —— 只能走主题变量桥与受控 CSS 两条公开通路。
- 支付 / 授权 / 系统安全页 / 未开放根 —— 保持原生，工具不生成它们的规则。
- 角色卡的人设、开场白、世界书、存档数据 —— 工具不碰人设（`personality` 从不写入）；`beginning` / `statusbar` 只用来满足导入页的字段要求，默认是空串，**给已有卡导入前请把它们填成卡里原本的值**。

**工具主动避开的坑**：

| 平台限制 | 工具的处理 |
| --- | --- |
| `replaceString` 上限 20000 字（超了作者一进编辑器就被截断） | 拆成多条规则，右上角有容量进度条 |
| 匹配式不建议带 HTML 标签与 `html/head/body/css` 保留字 | 全部用 `{{skin-xxx}}` |
| 替换内容禁止 `*{}` / `html{}` / `body{}` / `:root{}` | 所有选择器从 `[data-chat="root"]` 开始；自定义 CSS 里的全局选择器会被自动改写并报错 |
| 自写 `data-*` 会被净化删掉 | 按钮只用 class 与 id，自定义类统一 `mmdskin-` 前缀 |
| 作者层 z-index 只能用 1000–1999 | 粒子 1000、开关按钮 1500 |
| 宿主 CSS 过滤 `:has()` / `url()` / 原生嵌套 | `skin-host` 单独一条规则、平铺书写、只用圆角与中性描边 |
| 不能改 `header`/`list`/`message`/`composer`/`toolbar` 的定位与内外边距 | 顶栏不加 `position`；气泡内边距写在 `message-body` 上；尖角感用圆角实现，不用伪元素定位；消息间距只动 `row-gap` |

> 自测抓到过的真 bug：
> 1. 源码注释里一个未转义的 `</script>`——浏览器会在那里把**整个脚本截断**（当时贪心抽取掩盖了它，改成精确判定后才炸出来）；

> 3. 配色提取**按明度排会挑反强调色**——暗色主题的强调色常常比亮色主题的还亮。改成「块配对 + 按主题分别判策略」后才对。

## 修过的坑（v1.0 → v1.2）

都是真实使用中撞出来的，逐条记下来免得再犯：

| 现象 | 根因 | 现在怎么守着 |
| --- | --- | --- |
| **皮肤把卡自己的界面一起渲染了** | 卡的 UI 住在消息区里，被皮肤当成气泡改了盒模型（内边距/最大宽度/行间距/头像尺寸/transform）；另外根节点上被我强行写了 `background-color`，会盖掉卡自己画的整页背景 | 默认开启「🛡️ 不动布局」：不写这些属性并显式 `revert`，相关滑杆自动隐藏；根节点不再写 `background-color`；新增 2 条断言（安全模式的布局属性只能是 revert / 根节点不许有 background-color） |
| **再次导入有残留**（新配色配旧圆角） | 平台的样式是合并表，我对"关掉的开关"是**不写属性**，旧皮肤写过的值就赖着不走 | 每个「关掉」的开关都显式写 `revert`；新增断言：19 种关掉状态逐个验证有 revert |
| **导进去了但一点效果都没有**（导入页不报错） | 导出是**单行紧凑**的 JSON。实测：同样的内容，单行紧凑导入后规则不生效，缩进多行才生效 —— 平台内部行为，原因不明 | 只出缩进多行，「JSON 排版」选项删掉；新增断言：导出必须是缩进格式 |
| **导入报「格式错误」** | 导出顶层只有 `chatVersion / pageDepth / regex_scripts`，**少了 `statusbar` 和 `beginning`**（平台自己导出的 4 份文件里这两个键一个都没少）；规则的 `id` 还用了 `-1/-2/-3…` 而平台每条都是 `-1`；另外是多行缩进、还把脚本结束标签转义了 | 导出形态与平台对齐：五键齐备、**默认缩进多行**、不再转义、**规则 id 一律 -1 且键顺序一致**；新增「导出形态」积木区（可填自己的 statusbar / beginning）；新增 5 条断言（形态 / id / 与真实文件对照 / 缩进往返 / 哑巴控件审计扩展到导出文本） |
| **日间主题下顶栏/功能栏是深色的，字糊在底色里**（导出的包也一样，不只是预览） | `buildLayoutCss` 里写死了 `activePalette(s, 'dark')`：顶栏/功能栏/底栏的底色与渐变都是**按夜间色板算出来的死色值**，不跟 `data-theme` 走；而文字色用的是当前主题的 `--chat-text`（日间是深色）→ 深字压深底 | 组件颜色全部改成主题令牌（`--mmdskin-header-bg` / `-bar-bg` / `-composer-bg` …），在**每个 `data-theme` 变量块里各算一份**；新增「主题自适应」+「主题令牌逐块校验」两条断言 |
| **复选框勾上以后再也取消不掉**（顶栏/底栏/功能栏这三块几乎全是复选框） | Chrome 点复选框会**先 input 再 change**；`input` 阶段 `e.target.value` 是字符串 `"on"`，写进 state 就成了 truthy 的字符串，`syncInputs` 一看 `!!v` 就把框重新勾上，随后 `change` 读到的 `checked` 又已是 true —— 状态就锁死了 | `input` 处理器对复选框让路（只由 `change` 写布尔值）＋ `applyControl` 用 `coerceControlValue` 把值强制成**默认状态里的类型**；新增 3 条断言（9 组类型强制 + 结构断言 + 类型自洽） |
| 悬浮的开关按钮跑到整个浏览器窗口右下角 | `position:fixed` 相对**视口**定位，Shadow DOM 只能隔离样式、拦不住定位 | 预览护栏加 `.mmdskin-float{position:absolute!important}`；新增「预览护栏」断言 |
| 胶囊（阴影强度等）点了高亮不切换，刷新后才对 | `applyControl` 只改了状态，没把控件视觉刷一遍；刷新时走 `init → syncInputs` 才正常 | `applyControl` 里补 `syncInputs()`；`syncInputs` 改成幂等 + 不碰正在输入的框（避免光标乱跳） |
| 「阴影强度」4 档在预览里长得一模一样 | `--mmdskin-shadow` 定义了但**没有任何 `var()` 引用**，顶栏还硬编码了一个固定阴影 | 顶栏/功能栏/开关按钮改用 `var(--mmdskin-shadow)`；新增「死变量审计」断言 |
| 「界面圆角」滑杆怎么拖都没变化 | 同一个死变量的受害者 | 换成顶栏的「底部圆角」（真的会改 `border-radius`），删掉那个假滑杆 |
| 「粒子闪烁」开关没有效果 | 闪烁动画是无条件附加的，没读 `twinkle` | 动画列表与 `@keyframes` 都跟着开关走 |
| 毛玻璃看不出效果 | 底色不透明，`backdrop-filter` 没有可透的东西 | 毛玻璃开启时底色改半透明（`rgba(...,0.78)`） |
| 顶部色板下拉和实际配色不一致 | `随机配色`/参考图取色/载入方案/医生套色/重置 都不经过控件层，只有面板里的下拉会同步 | `update()` 里统一 `syncQuickPreset()` |
| 提示文字被挤成一列一个字 | `.mini-note` 掉进 flex 容器，成了胶囊按钮旁边的兄弟项被压扁 | `.ctl{flex-wrap:wrap}` + 提示占满整行 |
| 8 个空转的派生变量 | 早期版本的半成品令牌 | 全部清掉，只留真正被 `var()` 用的 |

## 已知边界（诚实清单）

- **浏览器渲染未实测**：本机 DSH 沙箱挡住了 Chromium 的 mojo 管道（`platform_channel.cc: 拒绝访问`），无法跑无头截图。UI 观感、拖滑杆手感、预览里的粒子密度、**拖图取色的实际手感**、医生面板的排版，都需要你自己开一眼确认。逻辑层与接线层已有自动化证据（见上）。
- **皮肤医生是只读的，不自动改写旧包**：它只报告问题 + 扒配色，迁移靠「扒配色 → 套进积木面板 → 重新生成」。自动重写别人的 CSS 风险太大，我没做。
- **宿主弹窗静态通过 ≠ 线上生效**：平台是「抽取 + 过滤后注入父页面」，是否注入取决于目标站点版本，必须打开真实弹窗核对根命中与计算样式。
- **18 个主题变量桥的同步范围**未知全量：记忆管理 / 模型 / 人设等入口是逐个接入的，可能有的已接、有的仍是原生色。
- **一键开关管不到父页面**：`[data-host]` 细化规则在另一个文档里，iframe 的类影响不到它；关掉美化后弹窗细化可能仍在。工具里也写在提示里。
- **输入框白底的 `:has()` 配方**来自平台公开文档，目标页内核太老时可能不生效（输入框本体仍保持透明底）。
- **头像选择器**按公开结构定位 `[data-chat="header-title"]` 里的图片 / 首个元素；结构不同则不命中，删掉那条规则即可。
- 气泡内边距写在 `message-body` 上，平台自己那层内边距会叠加，实际留白比滑杆数字略大。
- **拆条的边界**：拆点只落在花括号深度 0 的地方。如果你单条自定义 CSS 里有一行本身就超过 18500 字，那行无法再拆，超限会在「自检报告」里报出来。
- **分享链接在本地 `file://` 下只对自己有意义**：别人要有同样路径的文件才打得开。工具是单文件，挂到静态托管上就能真正分享了。
