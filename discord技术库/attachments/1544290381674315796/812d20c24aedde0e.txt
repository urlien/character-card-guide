【输入框"精准替换而非重复插入"书写规范】

适用场景：点击按钮把预设文本填入输入框（textarea/input），且这个按钮
可能被反复点击、或与其他"同类填入按钮"交替点击。

请按以下规则实现点击事件：

1. 用一个模块级/全局变量记录"上一次由脚本自动填入的文本"，
   命名格式：window.__<组件前缀>LastActionText
   （初始为 undefined，不要用空字符串占位）

2. 定位输入框元素（querySelector 选择器要精确匹配目标输入框，
   避免误选到页面上其他 textarea）。

3. 点击处理函数内，按此顺序判断：

   a) 取出本次要填入的目标文本 newText。
   b) 若 newText 为空，直接跳过，不执行任何操作。
   c) 读取全局变量 prevText = window.__xxxLastActionText。
   d) 判断 "prevText 存在 且 输入框当前内容包含 prevText"：
      - 是 → 说明上次填入的内容还完好地留在输入框里（用户没有动过它）：
          - 若 newText !== prevText：
              用 输入框.value.replace(prevText, newText) 做替换
              （只替换第一处匹配，不新增文本）
          - 若 newText === prevText：
              什么都不做（防止重复插入同一段）
      - 否 → 说明输入框里已经没有上次的痕迹
             （用户手动改过 / 这是第一次点击）：
          - 按"插入新内容"的方式处理：
            拼接到已有内容前面或后面（视需求而定），
            并且如果原内容非空且没有以换行结尾，
            要补一个换行符做分隔。
   e) 无论走哪条分支，只要发生了改写，都要：
      - 触发一次 input 事件（{ bubbles: true }），
        通知框架/其他监听器输入框内容变化了
      - 让输入框重新获得焦点（.focus()）
      - 把 window.__xxxLastActionText 更新为本次填入的 newText

4. 关键约束（必须遵守）：
   - 判断"是否要替换"的依据永远是"输入框当前内容里是否还包含
     上一次自动填入的原文"，而不是"输入框是否为空"或"按钮是否
     被点过"，这样才能区分"用户手改过内容"和"没动过"两种情况。
   - 替换操作只做一次 string.replace（默认只替换第一个匹配），
     不要用全局替换（避免误伤用户手打的相同文字）。
   - 全局变量的作用域要能跨多次点击存活（不能是函数内局部变量），
     且如果页面上有多组"填入按钮"，各自要用不同的变量名区分，
     避免互相覆盖判断逻辑。
