## 两条样式通路与过滤边界

| 内容所在位置 | 写法 | 已知边界 |
| --- | --- | --- |
| 沙盒聊天页、作者功能栏、舞台、指令栏 | `[data-chat]`、`[data-slot]`、作者 class/id | 当前沙盒可用 `:has()`；作者自写 `data-*` 会净化删除 |
| 宿主弹窗 | 每个选择器直接从精确的开放 `[data-host="…"]` 开始，随后空格或 `>` 加已核对的内部 class | 不带作者根前缀；不能跨沙盒读取或改写宿主 DOM |

- 作者规则 `<style>` 中的宿主样式会被抽取、过滤后注入。只含样式/脚本的规则装卡即加载，不需要匹配一个实际可见锚点。
- 宿主规则写平铺 CSS。原生嵌套整条丢弃；声明含 `url(` 会丢弃。当前实际宿主注入表丢弃了 `:has()` 选择器，不能照搬沙盒配方；也不假定复杂伪类、父级选择器均可通过。
- 平台会提高注入规则的选择器优先级；曾观察到重复根属性。作者仍只写一个根，不抄过滤器生成的重复形式。`!important` 可用于确有原生覆盖的属性，但不保证能覆盖所有平台内部样式。
- 内部 class 是当前实现的取证，不是稳定契约。`data-host-model-op` 等内部属性同样只作识别线索，不能推导公开调用接口。
- 不能改平台文案、图标、价格、权限和真实业务处理。主题通过 CSS 作用于原生控件，不复制虚假的模型列表、设置表单，不用本地存储假装保存了平台设置。
- 不覆盖宿主 `transform` 来居中，它可能参与开场动画或软键盘避让。只有确认祖先布局后，才尝试根的尺寸/位置重排，见配方。
- `persona-confirm` 是独立树，不在 `persona` 后代中。相同 `models` 根还覆盖模型帮助层，必须分别处理。
- HTML 小字用允许的 `span` 加 class 和 `display:block`；实际 `<small>` 被净化后文字挤在一行。抽屉容器使用 `div`/`details`/`summary`，不要使用未列入白名单的 `aside`。

## 交付与验收

换肤代码放正则包的替换内容，保留完整合法的 `chatVersion`、`regex_scripts` 等导入结构，见[角色字段与导入](role-import.md)。世界书仍是独立导入文件，只负责给 AI 的内容；样式、选择器和平台菜单不写进世界书。用户要求完整卡时交完整人设/世界书/正则，不能只交 CSS 冒充可导入角色卡。

验收必须区分：手册范围、当前 DOM、静态检查、本地复现、平台导入后实测。重点检查多模式选中态、长内容与窄屏滚动、确认/取消可见、指令返回后所有入口可点击、舞台低于侧栏、软键盘避让。未经授权不为了验收触发付费生成或破坏性操作；保留真实原生行为，不因未测保存就声称持久化已通过。
